# `mockblocks`

## Overview

A fork of scratchblocks that makes it easier to create mockups of block-based code, including blocks, categories and shapes that do not exist in Scratch. It is not merged back upstream.

The public global and package name is `mockblocks`. The text syntax is the scratchblocks syntax.

## Layout

- `index.js` builds the public API (`parse`, `render`, `renderMatching`, `newView`, `loadLanguages`, `stringify`). `browser.js` and `browser.es.js` are the bundle entry points.
- `syntax/` is the parser and model. `syntax.js` is the parser, `model.js` holds `Block`, `Input`, `Script` and friends.
- `syntax/registry.js` holds the registered categories (with colors for both themes) and packs. `syntax/blocks.js` holds the block lookup tables and `registerPack()`, which is how every block gets in, including the built-in ones.
- `syntax/packs/` holds packs that ship with mockblocks. `scratch.js` is the Scratch palette (its block list lives in `syntax/commands.js`, which the locale builder also reads) and is the only pack registered at load. `jscratch.js` mocks up the "Advanced language features" section of the [jScratch roadmap](https://github.com/AstroBlocksMod/jScratch/blob/main/docs/roadmap.md); jScratch has not designed those blocks, so do not add blocks to it that the roadmap does not describe, and check the roadmap again before changing it. Add new block sets as packs, not as edits to the Scratch pack, and expose them on `packs` in `index.js`.
- `syntax/color.js` derives secondary and tertiary shades from one color, so a pack category only needs `{ color: "#hex" }`.
- `syntax/shapes.js` describes shapes as features (`top`, `bottom`, `mouth`, `output`, `ring`). `info.shape` on a block is still a name (`"stack"`, `"hat"`, `"c-block"`, `"hat c"`, or a pack's own name), and `Block` resolves it to a feature object on `block.shape`. Code must read `block.isHat`, `block.hasScript`, `block.shape.top` and so on rather than compare shape name strings. The renderer composes the outline from the features, so any combination (a hat with a mouth, a cap with a define top) draws without new code.
- `scratch3/` is the renderer. It draws the Scratch 3 look in two styles, `scratch3` and `scratch3-high-contrast`. `draw.js` builds SVG paths, `blocks.js` lays blocks out, `css.js` generates the stylesheet from the registry at runtime (so it must not be a static `.css.js` string). There is no Scratch 2 renderer; it was removed from the fork.
- `locales/` is generated by `npm run locales` from `scratch-l10n`. Do not edit the JSON by hand except for the `mockblocks:` ids.
- `tests/` has the Jest parser tests. `snapshots/` renders scripts to PNG with puppeteer.

## Packs

A pack is a plain object: `{ name, categories, shapes, blocks, aliases }`. A block's `shape` can be a registered name, shape words such as `"hat c"`, or a feature object such as `{ top: "hat", mouth: true }`. Register it with `mockblocks.registerPack(pack)` (or `registerPack` from `syntax/index.js`). Registration is all or nothing: an invalid block, category or alias throws and leaves the registry untouched. Category names become CSS classes (`.sb3-<name>`), so they must be simple identifiers. The page stylesheet is regenerated when a pack is registered after `appendStyles()` ran.

## Overrides

`applyOverrides()` in `syntax/blocks.js` handles the words after `::`. Shape words (`hat`, `cat`, `define`, `c`, `cap`, `stack`, `reporter`, `boolean`, `ring`) are applied in order on top of the block's own shape through `applyShapeWord()`, and a registered shape name can be used as a word too. The resulting shape is stored under its canonical name, which is what `stringify()` prints. A hex color is stored on `info.color`; the renderer derives the three shades from it with `syntax/color.js`.

## Commands

- `npm test` runs the Jest tests.
- `npm run snapshots` renders every snapshot script to PNG. Rendering differs slightly between machines, so compare against a render you made yourself on the same machine, not against the committed PNGs, and only commit PNGs for snapshots you added. The snapshot page registers the bundled packs for every snapshot, so the Scratch snapshots also catch a pack that takes over a Scratch block.
- `npm run build` writes `build/`. `npm start` serves the dev page at <http://localhost:8000/>.
- `npm run lint` and `npm run fmt`.

## Verifying in a Browser

If you have it installed, use the Playwright MCP for this. If not, use the Playwright CLI instead. You can use the CLI over the MCP if you need to use a browser other than the one that is configured.

## Searching the Codebase

Use fast, modern tools instead of the slow defaults:

- [`rg`](https://github.com/BurntSushi/ripgrep) (ripgrep) for text search, not `grep`. It respects `.gitignore` for you. Prefer to use [`ast-grep`](https://ast-grep.github.io) when applicable as it uses the structure of the code instead.
- [`fd`](https://github.com/sharkdp/fd) for finding files by name, not `find`.
- [`ast-grep`](https://ast-grep.github.io) for structural searches and rewrites, like finding every call to a function or every component that uses a certain prop. Call it as `ast-grep`. The `sg` alias is deprecated, so don't use it.
- `jq` for reading and querying JSON.

If your harness has dedicated search or file tools that already wrap these, those are fine too.

## Code Quality

Always lint and format. Run `npm run lint` and `npm run fmt` before committing. Prettier is configured in `package.json` (no semicolons, trailing commas, no parens around single arrow arguments).

## Diagrams as Mermaid, not ASCII art

Never draw a flow, pipeline or architecture picture out of characters in a code block. Make a Mermaid diagram instead.

## Outdated packages

PLEASE, PLEASE do not use a package that is old or deprecated. EVEN IF IT IS "INDUSTRY STANDARD" THAT DOES NOT MEAN IT IS GOOD!!! USE THE BEST PACKAGE AND LATEST VERSION LIKE A NORMAL PERSON WOULD!

## Keep things human

Do no use em dashes or other special symbols not normally found in writing. Do not word things in a weird way. Keep it looking human. If you need to use, for example, an arrow icon, use an SVG instead.

Replacing an em dash with a hyphen is NOT a fix. A spaced hyphen doing an em dash's job ("the limit - 4 bytes", "fast - but wrong") is the same tic with a different character. Reword the sentence instead: use a comma, a colon, parentheses, or the actual word ("minus", "to", "through"). Plain hyphens in compound words and numeric ranges like 0-1 are fine.

## Use American spelling

It's fine to be British in the chat if the person is actually in a region where its spelled like that. But if not just use American spelling. The tool itself MUST use American spelling.
